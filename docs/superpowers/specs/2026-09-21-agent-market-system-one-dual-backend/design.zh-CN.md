# Agent Market System-One 双后端设计

## 1. 目标

为 Agent Market 增加一层与提供方无关的 System-One 决策平面，让 Laya 能在本地执行私密、低延迟的影子决策，同时保留 Jev 作为托管式对照后端。在通过特定任务的校准门槛之前，两者都不能获得路由、评分账本、争议处理、钱包、权限、随机性或结算权限。

## 2. 当前证据

现有 Jev 基础实现已提交于 `9902a797bb18fad0f877142cb3e671b860bd3172`。它定义了严格的匹配、质量、争议、阈值、回退和证据契约，但默认关闭，也尚未接入生产路由。

一次性本地试验在 Apple M5、Node `v22.23.2` 环境下运行了 `@receptron/laya@0.1.1`，并将 ONNX 模型固定到 Hugging Face 修订版 `68f27dfe5a27a54fb2b1fefc432f43f972e90868`。下载的计算图和数据文件符合以下 SHA-256：

- `laya.onnx`：`a874eb254b58b0fcb1e7ad56fbb188c29d64e08c9a46b689433e1f52c66dba1e`
- `laya.onnx.data`：`487746363a8da57bcadb4345352997d22a0fb90d70aa22c6856668d023242aba`

该模型占用约 1.6 GiB 磁盘空间，加载耗时 702 ms；面对合成的匹配、质量和争议输入时，预热后的 CPU p50 延迟为 99–169 ms。Laya 返回了有效分布，但匹配和争议的置信度只有 `0.113` 和 `0.1994`。

同样的三个合成输入也发送给了 Jev `1.13.0`。观测延迟为 275–1,842 ms。Jev 明确偏好确定性匹配候选人，对已完成结果给出高评分，但对争议路由的置信度较低。Laya 和 Jev 都返回了小数形式的期望分数（`3.183` 和 `3.97`），这暴露出现有 Jev 适配器只接受整数分数，会拒绝有效的线上响应。

这三个案例证明了兼容性并暴露出契约问题；它们不能证明比较准确率或校准质量。

## 3. 外部证据与限制

Laya 是采用 Apache-2.0 许可的开放权重模型，Node 运行时采用 MIT 许可。其文档报告了较好的本地延迟，以及带类型的 `choice`、`score` 和 `noul` 输出；但文档也说明，基础检查点在它的类型化决策基准上接近随机水平，报告中的领先结果来自基于该基准训练集微调的检查点，Jev 数据并非在同一次运行中测得，而且高基数选项仍是弱项。因此，Agent Market 必须把 Laya 当作一个需要校准的快速本地模型，而不是它优于其他方案的现成证明。

## 4. 不可妥协的权限边界

确定性宿主始终对以下事项拥有最终权限：

- 资格、能力、许可、健康度、预算、数据边界和风险门槛；
- 提供给决策提供方的候选池；
- 带种子的洗牌或 Chainlink VRF；
- 评分账本写入和信誉变更；
- Judge 独立性和允许的争议路由；
- 人工审核、钱包操作、权限、资金、合约和结算；
- 最终验证和发布批准。

Laya 和 Jev 只能在宿主提供的选项中提出建议，或返回期望分数。提供方结果只是证据，绝不是授权。

## 5. 架构

### 5.1 与提供方无关的契约

引入包含三个方法的 `SystemOneDecisionProvider` 接口：

```ts
type SystemOneDecisionProvider = {
  provider: "laya" | "jev";
  match(decision: AgentMatchDecisionV1): Promise<SystemOneDecisionResult>;
  scoreQuality(decision: AgentQualityDecisionV1): Promise<SystemOneDecisionResult>;
  routeDispute(decision: DisputeRouteDecisionV1): Promise<SystemOneDecisionResult>;
};
```

标准化后的观测结果记录提供方、实际模型修订版、所选值或小数形式的期望分数、概率、置信度、边际、延迟、可用时的用量，以及标准化结果的哈希。提供方特有字段不得泄漏到 Queen 或 Matcher 代码中。

### 5.2 Laya 提供方

Laya 适配器只在本地 Agent Runner 进程中运行。它从配置目录加载固定版本的本地 ONNX 包，任务执行期间绝不下载权重，默认使用 CPU，并把就绪状态与进程健康状态分开暴露。模型文件放在 Git 和浏览器包之外。

初始实现使用已验证的英文检查点，因为 Agent Market 发送的是分桶后的英文代码和描述。多语言或微调检查点需要单独的冻结评估和新的固定哈希。

### 5.3 Jev 提供方

Jev 适配器继续运行在服务端，并沿用现有的 macOS Keychain 到环境变量的启动边界。它只发送不透明引用、HMAC、分桶属性、原因代码和允许的选项。它绝不发送原始提示词、对话、源代码、本地路径、钱包、凭据或数据库行。

线上响应解析器必须接受从 `0` 到 `4` 的小数期望分数，而概率标签仍然是从 `0` 到 `4` 的离散等级。

### 5.4 双影子协调器

本阶段唯一新增的可部署模式是 `dual-shadow`。对每个符合条件的抽样决策：

1. 运行确定性基线。
2. 在本地运行 Laya。
3. 当远程对照预算和隐私政策允许时，可选地让 Jev 在同一份脱敏状态上运行。
4. 标准化并验证两个结果。
5. 记录一致、分歧、弃权、延迟、模型版本和结果哈希。
6. 无论提供方输出为何，都把确定性基线返回给宿主工作流。

本阶段不存在 `laya-primary` 或 `jev-primary` 模式。模型缺失、密钥缺失、超时、分布格式错误、选项超出候选池、低置信度、低边际或提供方之间存在分歧时，都必须保留确定性结果。

## 6. 配置与生命周期

配置必须显式设置，且默认关闭：

```text
SYSTEM_ONE_SHADOW_MODE=off|dual-shadow
LAYA_MODEL_DIR=/absolute/pinned/model/path
LAYA_MODEL_REVISION=68f27dfe5a27a54fb2b1fefc432f43f972e90868
LAYA_TIMEOUT_MS=2000
JEV_SHADOW_ENABLED=false
JEV_SHADOW_TIMEOUT_MS=3000
```

`TYPESAFE_API_KEY` 仍然只能作为机密输入，绝不能存进配置文件。启动时必须先验证 Laya 文件哈希，之后才能把提供方标记为就绪。关闭时要释放 ONNX 会话。把 `SYSTEM_ONE_SHADOW_MODE=off` 作为熔断开关，而且关闭模式不得要求模型或密钥。

## 7. 评估与晋级门槛

现有六个合成案例继续作为契约测试，而不是准确率证据。晋级需要一套冻结、带标签、已脱敏的数据集；数据应来自 Agent Market 的决策形状，并包含困难案例和负面案例。

对每种决策类型，从以下方面比较确定性基线、Laya 和 Jev：

- 精确选项准确率或分数 MAE；
- 弃权后的选择性准确率；
- 覆盖率和回退率；
- 硬过滤违规和候选池外违规，两者都必须保持为零；
- Brier 分数和期望校准误差；
- p50/p95 延迟和本地内存用量；
- Jev 请求量和实际成本；
- 关键错误路由，必须保持为零。

在冻结盲测通过、阈值完成版本化，并且影子观测窗口内权限违规为零之前，任何提供方都不能获得最终决策权。即使晋级之后，高风险争议也始终保留人工或宿主审核。

## 8. 证据与隐私

证据只能存储：模式版本、决策类型和不透明 ID、提供方、策略与模型版本、输入形状 HMAC、结果哈希、置信度、边际、延迟、用量、是否与基线一致、接受／弃权／回退状态，以及回退原因。

证据不得存储 API 密钥、原始提示词、私聊消息、源代码、本地路径、钱包身份、完整 Agent 输出或生产数据库记录。

## 9. 部署与回滚

本阶段只部署到本地 Agent Runner。它不创建任何 AWS、Cloudflare、数据库、链上或付费共享资源。ONNX 包必须在启动前预置并通过哈希验证。生产推进顺序如下：

1. 修复小数分数解析器；
2. 在测试保护下增加与提供方无关的契约和适配器；
3. 运行冻结的离线对照；
4. 在本地启用无权限的 `dual-shadow`；
5. 观测并审查 Evidence；
6. 在后续变更中决定任一提供方是否获得有限权限。

回滚方式是将 `SYSTEM_ONE_SHADOW_MODE=off`，重启本地 Runner，并按需卸载外部模型缓存。整个过程中，确定性路由路径保持不变。

## 10. 验收标准

- Node 22 测试和类型检查通过。
- 真实的小数 Jev 分数可以在不四舍五入的情况下被接受并标准化。
- Laya 能从固定的本地模型包运行，且不访问网络。
- 两个提供方都拒绝格式错误的分布和候选池外选项。
- 双影子模式绝不改变确定性路由、评分账本、争议状态、洗牌、权限、资金、钱包或链上状态。
- Laya 文件缺失和 Jev 凭据缺失时，系统安全回退到确定性基线。
- Evidence 不包含任何被禁止的原始字段或机密字段。
- 不创建新的 AWS、Cloudflare、数据库或链上资源。
